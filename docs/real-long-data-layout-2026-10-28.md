# 真实长日记副本的布局分析

## 数据与测试边界

从本机数据目录冻结复制 `journal.json` 和 `Images`，每次运行再复制到独立临时目录，使用正常可编辑的 `JournalStore`。原数据不参与测试写入。正文、标题、标签名、记录标识和图片均不进入仓库；诊断仅输出数量、宽度和耗时。

本次副本的四个页面：

| 页面 | 条目 | 正文 UTF-16 长度 | 图片 |
| --- | ---: | ---: | ---: |
| 文字最多的日记 | 49 | 19,311 | 0 |
| 第二组长日记 | 84 | 7,350 | 6 |
| 文字最多的标签笔记 | 80 | 9,627 | 29 |
| 条目密集的任务笔记 | 33 | 2,122 | 0 |

最长单条正文为 12,637 个 UTF-16 单元。这里的长度不包含 Markdown 渲染后的额外属性，图片也随副本一起保留。

使用 Release 构建、1424 × 876 隐藏窗口、1.1 倍字号、4500 pt/s，按约 120 Hz 显示回调依次向上、返回、再次向上滚动。每遍至多 8 秒。测试包含原生 NSTextView 对照，区分滚动、同步布局、绘制请求和主队列等待。

这些数字衡量主线程同步工作和错过的刷新机会，不是屏幕实际呈现 FPS，也不包含触控板到像素的完整延迟。首次遍历会受懒加载高度修正影响；稳定遍历的距离与首遍分别比较。

## 定位到的重复工作

开启 `TIMELINE_LAYOUT_DIAGNOSTICS=1` 后，统计正文视图创建、更新、宽度提案、富文本缓存命中、TextKit 测量、原生布局和行 body 求值。正式性能比较关闭诊断，避免计数与锁影响结果。

初次基线中，长日记再次向上遍历时提出了 1504 次正文尺寸询问，全部命中高度缓存，新增 TextKit 测量为 0。尺寸询问自身仅约 0.21 ms，整遍同步布局约 450 ms。另一组日记也有 3429 次询问、0 次新增测量，而整遍布局约 839 ms。继续增加高度缓存解决不了这里的主要开销。

采样中可见大量 SwiftUI 视图列表创建、AttributeGraph 更新与 StackLayout 尺寸协商。时间轴左侧原先用一个透明视图与正文放进 HStack；HStack 为分配宽度，反复向整个正文树询问 0、1、实际宽度和无限宽度。改为等宽的 leading padding 后，主体只收到实际宽度。在行创建数相同、各重建 22 个正文视图的一组长日记再次遍历对照中，尺寸询问由 754 次降到 80 次；另一组日记的修改后诊断为 178 次。正文起点仍为行左侧 88 pt，右侧仍保留 8 pt。

另一个独立峰值出现在 `TaskLinkText.updateNSView` 中：赋值 `needsDisplay = true` 会进入 `NSTextView.setNeedsDisplayInRect:avoidAdditionalLayout:`，接着填充 TextKit 布局。新建正文此时还没有实际宽度，文本容器只有 1 pt，长文因此先经历一次非常窄的排版，再按最终宽度重排。这部分没有经过独立的测高器，仅查看测高计数会漏掉。

这处原生显示栈的峰值本轮仍保留。对重绘时机、初始容器宽度、零尺寸更新和自动伸缩的尝试，出现了笔记页 p95 回退，或者没有通过极窄容器的回归，均已撤回。因此不能把中间方案测到的约 50 ms，甚至约 28 ms 峰值写成最终版本的收益。

最终功能改动仅为左侧留白布局简化，补充回归验证三个字号与三种窗口宽度下长 Markdown 的位置、高度、完整换行和链接区域。正文仍保留原来的尺寸与重绘协议。

## 复测原则

保留了原实现及中间实现的独立测试可执行文件，检查其 Mach-O UUID 不同，再交替运行同一冻结副本。原实现自身也存在明显波动：长日记再次遍历的 p95 在不同运行中为 8.42 / 3.31 ms，第二组为 13.25 / 6.56 ms。因此首轮中看起来接近减半的 p95 不能直接作为稳定收益。

交付前在最终代码上重新运行完整回归及真实副本探针，最终结果与中间实验分开记录。

## 最终版本结果

完整回归之后，按「最终版 / 原实现 / 最终版」串行运行同一冻结副本，每次均为新进程，关闭布局诊断。每次探针 6 项通过。下表记录移动帧同步工作的 p95 / 最大值，单位毫秒；最终版两次测量分列，不取最好的一次。

| 页面与遍历 | 原实现 | 最终版第一次 | 最终版第二次 |
| --- | ---: | ---: | ---: |
| 长日记，首次向上 | 4.59 / 128.54 | 3.71 / 127.77 | 3.85 / 127.75 |
| 长日记，再次向上 | 3.39 / 128.24 | 3.37 / 127.67 | 3.41 / 128.16 |
| 第二组日记，首次向上 | 9.01 / 61.69 | 8.02 / 49.44 | 7.90 / 48.68 |
| 第二组日记，再次向上 | 6.78 / 28.23 | 6.46 / 28.08 | 6.97 / 27.93 |
| 图片标签笔记，首次向上 | 8.36 / 233.07 | 8.38 / 190.70 | 8.19 / 190.96 |
| 图片标签笔记，再次向上 | 3.04 / 4.38 | 2.72 / 4.38 | 2.73 / 4.20 |
| 任务笔记，首次向上 | 0.61 / 0.72 | 0.60 / 0.75 | 0.64 / 0.88 |
| 任务笔记，再次向上 | 0.91 / 1.01 | 0.53 / 0.72 | 0.55 / 0.87 |

稳定遍历距离保持一致：长日记 10,965 pt、第二组日记 7,377 pt、图片标签笔记 13,908 pt、任务笔记 1,325 pt。本组三轮首次长日记也都为 80,947 pt，图片标签笔记都为 9,707 pt；第二组日记约为 8,135 / 8,162 / 8,140 pt，仍有懒加载估计的轻微差异。

同步打开时间也没有因预加载增加：长日记原实现约 393 ms，最终版约 307 / 284 ms；第二组约 75 → 71 / 71 ms；图片标签笔记约 145 → 135 / 137 ms；任务笔记约 150 → 149 / 148 ms。打开计时不包含等待异步任务完成，因此不是页面完全就绪的总时间。

本轮可以确认减少了重复的宽度协商，第二组日记与图片笔记首次遍历的峰值有所降低。长日记约 128 ms 的尖峰仍在，第二组日记稳定遍历的 p95 也没有一致下降，不能声称已整体达到浏览器的跟手程度。不要将早期基线的较大 p95 与最终版直接相减，得出大幅提速的结论。

原生文本对照首次遍历 p95 三轮分别约 3.35 / 3.33 / 3.33 ms，再次遍历约 4.66 / 4.44 / 4.68 ms，并未随最终版整体变快。这里仍保留系统调度与窗口隐藏带来的测量限制。

最终完整 Release 回归 717 项，22 项按条件跳过，零失败，包含编辑器对齐、就地编辑、Markdown 折叠、链接、图片和窗口守门测试。窗口服务器监控的两段日志均未发现可见测试窗口。

## 后续方向

标签笔记首次遍历仍有较大的视图创建和布局峰值。单独采样看到主要工作仍在 SwiftUI 列表展开与 AttributeGraph，另有图片尺寸读取和 Markdown 渲染；当前证据不足以把整个峰值归因于图片解码。图片解码本身已有后台队列，下一轮应对冷行挂载、图片占位尺寸更新及每个刷新周期创建的条目数进一步分段计时，再验证是否值得分批准备。

长文的另一个后续重点是显示用 TextKit 栈：记录容器宽度被重置的时刻、重绘请求触发的排版与最终宽度下的排版，找到可以取消的中间布局。已有独立测高缓存命中，仍可能在显示栈里发生昂贵排版；两部分需要分别分析。

懒加载的高度估计也仍会调整首次浏览的位置。增加整页预加载会把滚动成本搬到打开页面，必须同时测打开时间与内存，不能只比较滚动 p95。

## 复现

先运行相关回归并生成 Release 测试构建，再运行真实副本探针：

```sh
swift test --disable-sandbox -c release \
  --filter 'AAAWindowWatchTests|NoteThreadLayoutTests|TextLayoutReuseTests|TextLayoutInvalidationTests|ZZNoVisibleWindowsTests'

TIMELINE_REAL_LONG_PROBE=1 \
TIMELINE_SCROLL_PROBE_DATA=/path/to/frozen-copy \
TIMELINE_FRAME_PROBE_OUTPUT=/tmp/timeline-real-long-results \
swift test --disable-sandbox -c release --skip-build \
  --filter 'AAAWindowWatchTests|ScrollFramePerformanceTests.testDisplayPacedLongestRealDataPages|ZZNoVisibleWindowsTests'
```

副本目录至少含 `journal.json`，有图片时同时复制 `Images`。可用 `TIMELINE_REAL_LONG_PAGE` 选择 `real-journal-longest`、`real-journal-dense`、`real-notes-tag`、`real-notes-task` 单独采样。性能探针不会把真实内容写入报告；原始副本仅放在本机临时目录。
