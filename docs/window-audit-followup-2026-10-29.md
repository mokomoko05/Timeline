# 窗口与日志交互审计修正

本轮跟进 `22c257b` 至 `cce3024` 的源码审计。原来的位置夹取不能直接用于用户拉边缩放：只改原点、保留扩大的尺寸，会把固定的对边推走。两个窗口基类现在在 `inLiveResize` 时裁剪超出可用区域的边缘；程序调整尺寸、保存位置恢复和屏幕变化继续使用位置约束。原本超大、离屏或受最小尺寸限制而无法裁剪的窗口保留原有兜底策略。

相邻屏幕的可见区域现在允许跨屏，拖动过程中不用等最大重叠屏幕切换。算法合并连续的矩形通道，不直接使用所有屏幕的外接矩形，防止把错位显示器的空白角落、屏幕间空隙和 Dock 区域也当成可用空间。窗口完全离屏时仍回到首选屏幕；尺寸大于所有可用通道时保留原有尺寸和左上角可操作区域。

日志双击原来已有 `onEdit` 入口，因此“完全不能进入编辑”并非所有页面都会发生；确实存在的是双击绕过预备编辑器、丢失点击位置的路径。现在预备完成时向 WebKit 转交原始事件，包括点击次数；尚未完成时在点击处编辑，并在配置好后选中对应单词。首击只选中、后台延迟预备，仍不滚动、不进入编辑。

事件监控器只从 `MainActor.assumeIsolated` 返回 Bool，在外层返回原始事件，消除把非 Sendable 的 NSEvent 作为隔离闭包返回值的警告。标题栏偏好明确支持 None 和 Minimize，其余值按默认缩放处理，包括 Fill 和未来未知值，不再静默吞掉双击。本机 `defaults read -g AppleActionOnDoubleClick` 显示未设置该值，走默认缩放；没有宣称已验证所有 macOS 版本的偏好编码。

保留仅选中后显示操作按钮，以及预留操作列的布局。这是此前明确要求的交互，能避免悬停触发整行变化和选中时重新换行，测试继续检查标题折叠按钮和操作按钮不重叠。

测试通过透明窗口和虚拟屏幕信息验证生产约束路径，包括反复拉左边、下边、角落和其余两边的 live-resize 状态，连续跨屏往返、垂直拼屏、错位屏幕、屏幕间空隙，以及冷/热编辑器双击。它们不能替代前台物理拖动和拉伸的手感验证；本轮没有移动用户鼠标或显示测试窗口。

完整回归首次发现既有 `NotesWindowTests.testSwitchingModesRetainsTheEditorsAndJournalScrollPosition` 的准备阶段失败。用 `/tmp/timeline-limit-final/TimelinePackageTests.xctest` 中此前归档的测试程序复测，得到相同失败（实际 y=4908，要求小于 4828）。原测试在第一次 layout 后立即发送 windowNumber=0 的合成滚轮事件，坐标没有变化；改为直接滚动也会在让出主线程后被初始定位覆盖。等待首次布局和今天的底部定位稳定后，原生 clip view 能滚至 y=2908 并保持。该测试现在等待初始可见区域稳定，再用 clip view 滚动并反映给 scroll view，明确断言已经离开原位置，同时保留原有切页、编辑器实例和滚动位置断言；没有更改生产滚动逻辑。

验证：相关 Release 回归 49 项通过；修正测试准备过程后，完整 Release 回归 735 项、22 项按条件跳过、零失败。AAA / ZZ 窗口守门全部通过，独立窗口服务器监控日志 0 行。本轮涉及的 NSEvent Sendable 警告已消失，编译仍有仓库原有的其他警告。编辑器资源通过 `cd Editor && npm run build` 重新生成。完整测试日志为 `/tmp/timeline-audit-full-final.log`。
