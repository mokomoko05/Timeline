# iCloud Drive 等待上传与 File Provider 协调

用户报告：在 Timeline 内反复点击同步，一直等待上传；打开系统「文件」App 后才完成。随后回读手机同步状态已确认上传，两端正式 SQLite 中的任务、日志、工作板逐实体内容一致。不能据此否认此前存在等待，也不能把暂时恢复当作问题已彻底消失。

代码审查发现，内容读写使用了 NSFileCoordinator，但新建 streams 等子目录、枚举设备/批次/图片维护目录未协调；授权目录只在每轮 I/O 时短暂访问，没有前台文件呈现关系。这些缺口不符合外部文档目录的访问约定，可能影响 File Provider 发现变化。现有证据尚不能证明哪一项触发了本次卡住。

本轮修改：

- 目录逐层创建、目录枚举和文件写入统一经过文件协调。普通内容更新使用普通写意图；根据 Foundation 的 NSFileCoordinatorWritingForReplacing 文档，即使采用 atomic rename 更新内容，也不应将它表述为替换文档身份。
- 自动同步开启期间持有安全作用域访问，注册目录 NSFilePresenter。文件变化合并为一次 0.5 秒防抖检查；停止自动同步（包括 iOS 进入后台）时移除 presenter 并平衡访问次数。后台同步仍由每次操作持有自己的访问。
- 状态诊断文件增加上传/下载等待标记、待传文件数/字节数和等待开始时间，不再只能从「finished」等阶段字符串间接判断。
- 增加独立的随机文件往返诊断。手机正常显示正式数据，仅在 transport-checks 随机子目录交换校验串，不增删任务、日志、工作板或同步记录，完成/超时后删除本次目录。开发启动参数为 `-syncTransportProbe <随机字母数字串>`；另一端原样回写 reply.txt 后才算成功。

63 项相关测试通过，覆盖目录协调、文件占位/增量同步、图片维护、SQLite 持久化、presenter 重复启停、无需轮询计时器即可发现远端修改、空闲不重复发布及随机往返校验。ZZNoVisibleWindows 守门测试通过，窗口监测未记录可见测试窗口。iOS Release 模拟器与真机构建通过。此前真机安装成功；本次工具栏结构修正后的安装状态见下文。

这仍然是通过 iCloud Drive 普通文件夹同步。公共 API 允许正确协调与监听文件，不能保证系统立即上传，也不能以重复改写文件、时间戳或回执来冒充重试完成；真实云端传输需要单独验证。

## 真机通道验证

正常界面下，仅交换随机校验串，未打开手机 Files。第一轮手机文件约 5.2 秒到 Mac，反向校验未完成；诊断自身曾把“文件本地存在”当作请求下载的前提，已改为协调枚举并无条件检查/请求下载。下载状态同上传状态一样，每轮用新 URL 取资源属性，避免 URL 缓存。

修正后第二轮双向校验完成：Mac 约 27.1 秒看到请求，手机从写出请求到读回正确响应约 42.2 秒。该实验说明无需手动打开 Files 也可以完成传输，但只有一个成功样本，不能宣称 iCloud 的调度长尾已消除或给出稳定延迟保证。

## 同步按钮交互

本机内容变化后显示同步状态，自动同步依次报告准备、检查、合并、保存、发布和等待。成功显示绿色勾选与“同步完成”，约 2 秒后隐藏整个按钮；使用 0.24 秒布局动画让相邻按钮向左收拢。等待/失败继续可见，允许重试并查看详情；支持系统的“减少动态效果”。草稿、无变化轮询和纯远端导入不触发本机修改提示。

状态对象只由小范围的按钮订阅，内容变化检查按主线程一轮合并，不让整页订阅高频动画。应用内防抖从 2 秒降为 0.5 秒；目录变化以 0.5 秒合并触发检查，15/30 秒定时器作为兜底。未改为持续重写云端文件来刺激上传。

后续若需要稳定秒级跨设备反馈，应评估 CloudKit 或有推送的服务同步元数据；免费签名加外部 iCloud Drive 文件夹的方案，应用无法指定系统何时上传。保留原图质量与增量传输不冲突，但更换传输层会涉及开发者账号、服务部署和数据迁移。

## 原生工具栏占位修正与模拟器测量

iOS 不能只隐藏 `ToolbarItem` 内部的 Button：iOS 26 的原生胶囊仍可能保留宽度。现已将可见条件放在 `ToolbarItem` 外侧，从工具栏结构中移除整个项目，覆盖待办、日记、笔记和工作板列表/详情。每个平台的同步控制器只持有一个反馈状态，切换页面不会重新开始完成倒计时；可见性对象只发布结构变化，阶段变化由小按钮单独订阅。macOS 也按相同条件插入/移除整个按钮。

iPhone 17 Pro / iOS 26.5 模拟器，Release，使用相同的隔离 SQLite 样本和临时共享目录，三轮“修改日志并点击同步”到下一帧：旧界面 37 / 36 / 36 ms，新界面 40 / 34 / 33 ms，中位数 36 → 34 ms。样本很小，不能据此宣称性能显著改善；新界面首次操作仍记录到 87 ms 帧间隙，后两轮 51 / 65 ms。另一次单轮检查为 24 ms，并确认完成提示和收起状态。

截图检查：完成时显示绿色 Sync complete 与日历按钮，收起后只剩最左侧的日历按钮，无空胶囊。三轮连续检查中前两轮在点按后 3 秒已收起，第三轮当时仍显示完成（倒计时从实际完成后开始）；单轮重测确认随后收起。Mac 的实际 NSHostingView 宽度测试确认本机修改后展开，自动完成后恢复初始宽度；空闲轮询不改变宽度。

这些测量验证本地同步流程、状态切换和布局，不是 iCloud 网络测速。按用户要求，后续先在模拟器验证；本轮工具栏修正后未再启动真机云端诊断，也未将真机切换到隔离数据界面。
