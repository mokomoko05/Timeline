# macOS 窗口贴边拖动

通用拖动器从 `NSEvent.cgEvent.location` 恢复屏幕坐标。AppKit 在窗口移动后可能按新的窗口原点构造这一坐标；对排队的窗口事件再次转换，会把窗口已经移动的距离叠加进去。

新增回归先在窗口尚未移动时生成一批 AppKit 事件，再依次处理。窗口原点应为 220、240、260、280，修改前实测变成 220、260、320、400。此前的排队测试直接注入了预先固定的屏幕坐标，绕开了这个实际转换问题。

现在生产路径直接采样 `NSEvent.mouseLocation`，跟随窗口坐标系之外的当前鼠标位置。积压事件只会重复当前目标，不会追赶旧位置或叠加窗口偏移。边界限制在提交位置前完成，保持既有屏幕可见区域规则。

另一个回归检查四个边缘各持续处理 100 个旧事件。它发现半点目标会被 NSWindow 取整，导致窗口虽然没有改变位置，却反复收到相同移动请求。现在目标原点先取整，再限制到屏幕范围；目标相同时不提交移动。

验证包含有标题栏和无边框窗口、四个边缘持续停留和拉回、排队事件、Board 的真实事件分发与反复点击 X、原生关闭按钮、正文选择和缩放边缘。自动化通过注入鼠标位置驱动隐藏窗口，不移动用户的真实鼠标、不向其他应用发送事件。仍需区分这些位置与事件回归和前台物理拖动的观感验证。

相关窗口回归 46 项通过；与条目选择改动合并后的完整 Release 回归为 726 项，22 项按条件跳过，零失败。AAA / ZZ 守门和独立窗口服务器监控均未发现可见测试窗口。
