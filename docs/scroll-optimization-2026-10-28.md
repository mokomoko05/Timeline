# macOS 日记滚动优化：导航失效与正文缓存

本轮保留 SwiftUI 列表、原生正文和 WebKit 就地编辑器，逐步验证小范围优化。没有改动日志数据格式或 README 功能描述。

## 实现与验证

1. 日记页面直接观察 `NotesWorkspaceNavigation`，不再把父宿主图中的日期、定位日志绑定传入另一个 `NSHostingView`。日期、搜索请求与定位日志真正改变时仍刷新页面。
2. `InteractiveTaskText.setFrameSize` 在尺寸和有效文本宽度均不变时直接返回，不再额外标记布局失效。宽度变化仍同步原生文本容器；已有的待处理内容布局不会被清除。
3. 链接、Markdown 勾选框、代码块和标题折叠按钮的区域按当前文字布局缓存，绘制、鼠标命中和光标区域更新复用结果。正文或属性变化后同步清空缓存；尺寸、内边距、文本容器、最大行数和截断方式变化后重新计算。观察者弱引用正文视图，并在视图释放时移除。

独立诊断运行临时使用 SwiftUI `_printChanges()`：滚动时日期和定位日志值没有变化，日记 body 却反复报告 `_date, _revealLog changed`。同一试验配置改为直接观察导航对象后，body 执行从 70 次降为 1 次。手工构造闭包形式的 Binding 仍然复现；最终实现移除了这两处跨宿主绑定。诊断打印已删除，采样与诊断运行不计入性能对比。

新增回归先在未优化实现中观察到重复尺寸设置导致布局失效，以及重复区域查询产生额外字形查询。缓存启用后，同一布局连续查询 30 轮的四类区域不再增加字形查询次数。

回归覆盖：跨宿主切换日期、隐藏后重新打开并定位指定记录、保留编辑器与滚动位置、文字选区、变窄后的换行、只改高度、内边距变化、宽公式的横向滚动条、只改链接属性而不改文字、替换正文、裁剪范围变化、代码与标题按钮位置，以及正文视图在关闭窗口后的释放。原生文字存储的系统延迟释放不作为立即释放断言。

## 测量约定

使用同一份冻结的 `journal.json` 临时副本与现有合成场景，在同一台 M2 Pro 的 120 Hz 屏幕上运行 release 基准。副本当天有 57 条记录、正文合计 2,287 个 UTF-16 单元，没有图片引用。每轮依次首次向上、向下返回、再次向上，速度 4,500 pt/s。编译、功能测试和性能测量顺序执行，不并发施加额外负载。

沿用 [滚动测量报告](scroll-frame-audit-2026-10-28.md) 的方法与限制：隐藏窗口里按刷新节奏更新原生 clip view，测量滚动、布局与绘制调用，不代表 WindowServer 最终呈现帧率或真实触控板输入到显示的延迟。

增加 `FRAME OPEN` 输出，计时范围为创建宿主、窗口和第一次同步布局及绘制调用，不包含随后的固定 1 秒等待，也不代表从用户点击到完整呈现的打开延迟。

## 未保留的尝试

尺寸去重、区域缓存分别测量后，都没有显示稳定的整页滚动收益，不能把减少局部工作当作已经解决跟手问题。两项保留有确定性回归覆盖的局部去重，不单独声称滚动收益。减少时间轴外层订阅、按按钮显隐去重发布，以及给滑块单独建立宿主也没有稳定收益，均已撤回。

曾试验让 41–80 条、正文不超过 16,000 个 UTF-16 单元且无图片的日记使用普通 VStack。当前副本同步打开工作从约 234 ms 增至 374–397 ms，滚动仍在不同运行间出现约 1–40 ms 的中位数波动，因此撤回。逐条时间轴的 GeometryReader 改为 Shape，以及把滑块放入独立宿主，也未显示稳定收益，均已撤回。最终仍沿用原有的 40 条懒加载阈值。

## 最终 release 结果

修改前一轮完整基准与最终构建使用相同的冻结副本。最终完整运行 8 项测试，并在两个新测试进程中各运行 6 项测试，复测个人数据副本；均零失败，没有跳过性能场景。

下表为移动帧的工作耗时 p95，单位 ms；最终副本列列出三轮范围，其余场景各取完整运行一轮。

| 场景 | 修改前首次向上 | 最终首次向上 | 修改前再次向上 | 最终再次向上 |
| --- | ---: | ---: | ---: | ---: |
| 原生文本对照 | 3.31 | 3.27 | 2.72 | 4.07 |
| 30 条合成日记 | 0.85 | 9.30 | 0.72 | 9.32 |
| 90 条合成日记 | 7.99 | 7.70 | 5.07 | 6.49 |
| 90 条任务笔记 | 4.67 | 7.59 | 8.36 | 7.69 |
| 冻结的日记副本 | 16.94 | 10.23–10.89 | 14.24 | 9.26–9.49 |

修改前同一副本的其他中间基准还出现过首次向上 p95 44.99 ms、再次向上 27.46 ms；只改局部缓存和订阅无法稳定消除这种波动。最终三轮首次向上的工作中位数为 5.27–5.34 ms，再次向上为 4.80–5.11 ms；修改前完整基准的较快样本分别为 3.25 和 2.03 ms。因此这里只能确认该副本的长尾与运行间波动减少，不能声称每帧都更快。

最终首次遍历有 88–94 个移动帧，其中 20–24 个工作耗时超过 8.33 ms；再次遍历有 102–103 个移动帧，其中 13–15 个超预算。首次遍历移动约 4,915–4,995 pt，再次均为 4,398 pt。首次遍历主线程最大间隔仍有 55–63 ms，不能声称已经达到浏览器般的连续滚动或稳定 120 Hz。

最终副本同步打开工作三轮为 201、187、180 ms；扩展预排策略已撤回，没有通过把全部排版搬到打开阶段换取滚动数字。

30 条合成日记本轮明显慢于修改前这次较快样本；先前测量报告里同场景也曾出现约 22 ms 的 p95。最终仍有随跨条目出现的约 9 ms 布局峰值，需要后续单独处理。90 条日记、长笔记的混合结果也不足以说明普遍提速。本轮交付范围是修复无变化的导航绑定导致的整页重算，并去掉可确定的正文重复工作，不是完成所有滚动优化。

最终完整输出位于 `/tmp/timeline-scroll-delivery-after`，个人副本复测位于 `/tmp/timeline-scroll-delivery-repeat-1` 和 `/tmp/timeline-scroll-delivery-repeat-2`。这些临时文件只用于本机复查，未提交个人日志数据。

## 验证

最终 `swift test` 共运行 703 项，21 项按默认条件跳过，零失败。滚动性能场景已在上述 release 运行中显式开启；窗口守门用例正常执行并通过。`scripts/test-window-monitor.swift` 在相关回归、性能测量与全量测试期间均未记录到透明度大于 0 的测试窗口。`git diff --check` 通过。
