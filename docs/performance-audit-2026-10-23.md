# Timeline 性能与生命周期审计（2026-10-23）

本轮从「确认创建 tag 后卡死」出发，检查主线程同步工作、SwiftUI 更新重入、窗口引用关系、通知订阅、定时器、图片识别和看板 WebKit 缓存。修改不涉及数据格式迁移。基准测试使用临时目录，实际 journal 只复制、不修改；报告不记录正文内容。

## 结论与已修复问题

| 操作 / 模块 | 发现的问题 | 本轮处理 |
| --- | --- | --- |
| 创建标签 | 在原生输入框处理回车 / 按钮事务时同步发布列表变化、保存、关闭 popover；锚点位于会更新的 LazyVStack 内，存在布局重入风险 | 抽出创建表单，验证后下一轮主队列提交，防止重复提交；popover 改挂稳定侧栏 |
| 打开 / 切换笔记 | NotesView.init 修改外部共享导航；空历史时 validate 会重复发布 nil；重复打开当前目标也发布状态 | 共享状态更新移到 onAppear；跳过无效赋值；新增不在构造阶段发布的回归测试 |
| 标签选择、搜索、拖动专注窗口 | 导航每次改变都重写五项偏好；所有偏好通知都会同步刷新专注窗口；窗口移动又写偏好，可能形成反馈链 | 仅写变化字段；专注面板只响应自身隐藏偏好变化，并延后刷新；跳过相同 frame、位置写入和重复 orderFront |
| 专注 / 看板 / 图片 / 设置窗口 | 持久保存的 LocalizedRoot 内容闭包通过 self 持有控制器；外层闭包可强捕获 self，即使内层动作标注 weak | 先构造内容或捕获模型，去掉内容构造闭包对控制器的反向持有；专注、看板、图片控制器弱引用释放测试通过 |
| 登录启动开关 | 主线程 waitUntilExit，无超时，系统命令变慢时冻结全部窗口 | 文件配置和 launchctl 移到后台；每条命令 5 秒超时，超时终止；配置中禁止重复触发。安装命令保留同步入口 |
| 草稿、日志、OCR 更新 | 每次 days 变化都查询通知权限、读取系统待通知队列、重加所有提醒 | debounce 后比较提醒计划；无变化不访问通知服务；已有请求匹配时不重加；同一时间的提醒顺序固定 |
| 图片 OCR | 同图多次引用会重复排队；每个日期只更新第一条引用，其他记录持续被视为未识别 | 图片名去重；结果写到全部引用；相同结果不发布；每张图片后释放临时 Vision / Foundation 对象 |
| 启动后图片清理 | 启动 8 秒后在主线程读取并扫描所有备份，备份较大时可造成突然停顿 | 扫描移到单个后台 utility 任务；回来重新检查当前图片引用，扫描期间发生保存则跳过清理；删除仍遵守图片宽限期 |
| 缩略图 | NSCache 未设置容量 / 成本预算 | 设置 128 项、64 MiB 解码像素成本预算（NSCache 是自动回收缓存，预算非严格内存上限） |
| 标签页章节 | 同一轮页面渲染重复收集、排序标签笔记与待办 | 章节构建复用页面已有快照 |
| 定时器生命周期 | 对象异常提前释放时，弱引用闭包仍可被 RunLoop 定时触发 | 专注会话和任务拖动视图析构时显式 invalidate 定时器 |
| 任务 / Markdown 原生文本视图 | NSTextView 继承的初始化入口重入 Swift 属性初始化，重复分配 TextMeasurer；最终持有的测量器可以释放，但先前分配的对象遗失 | InteractiveTaskText 显式实现指定初始化方法；独立最小复现中两个视图的测量器分配 / 释放从 4 / 2 变为 2 / 2 |

标签提交相关风险已修复，但没有获得用户那次卡死现场的主线程栈，不能断言某一条是唯一原因。回归测试覆盖实际创建表单的原生输入与回车、普通标签与多级标签，以及偏好反馈链和对象释放。

## 实测与验证

- 全量 `swift test`：516 项，0 失败；其中 1 项本地 journal 基准默认跳过，已另行显式运行通过。之后的文本视图初始化修复又通过 39 项相关回归（其中 1 项本地基准默认跳过）。
- 本地 journal 临时副本：41 个任务、421 条日志；连续创建 30 个标签，数据层耗时最小 / 中位 / 最大约 **4.50 / 4.78 / 5.93 ms**（debug）。不包含窗口渲染时间。
- 合成历史：1,000 个任务、10,000 条日志，创建 tag 约 **141 ms**（debug）；重载后的任务、日志数量及标签均正确。
- 看板生命周期：创建超过 6 个编辑器，最早的 session 和 WKWebView 均释放；释放导航后剩余 session 释放。脚本消息桥使用弱引用。
- 三类浮动窗口控制器的弱引用释放验证通过；修复前该验证可观察到对象未释放。
- 提醒验证：包括已有提醒的场景，写日志 / 改草稿不增加计划事件；修改任务标题会更新提醒；旧通知内容会被识别为不匹配。
- 登录启动命令超时验证使用独立 sleep 进程，不改本机登录启动配置；主线程在等待期间仍可执行任务。
- 图片清理验证覆盖当前引用、备份引用、孤立图片与宽限期。
- 旧版应用一次 2 秒空闲采样：CPU 读数 0.0%，物理 footprint 约 106 MiB，主线程等待事件。该快照没有显示持续忙循环，不代表所有交互路径均无问题。
- 新增测量器生命周期验证：100 次独立测量器及输入高度测量器创建、排版后，弱引用归零，包括 NSTextStorage、NSLayoutManager 和 NSTextContainer。仅验证最终实例会遗漏初始化过程中被覆盖的额外分配，因此还结合运行时扫描和独立分配 / 析构计数复现。
- 安装后 release 进程启动约 42 秒时运行 `leaks --noContent --nostacks`：**0 leaks / 0 bytes**，物理 footprint 约 67.6 MiB；此前同轮安装但未修复初始化的进程，普通扫描曾报告 658 个泄漏节点 / 80.3 KiB，根节点为 TextMeasurer。保守扫描仍可定位遗失的测量器实例，独立复现确认并修复了额外分配。不同窗口状态下的内存快照不能直接作为性能对比，也不能把单次扫描理解为所有路径零泄漏。
- 已正常退出并执行 `bash scripts/install.sh` 安装、打开应用；签名验证通过，安装前后的 journal SHA-256 一致。安装脚本已建立应用、数据、偏好及启动项备份。

## 同轮看板选区修复

浏览模式改用清晰的系统选区底色与文字色，覆盖编辑器隐藏原生高亮的样式；编辑模式也使用独立选区颜色，不再复用代码块的暗底。浏览时保留原生选区并隐藏重复的自绘选区，复制后高亮不清除，仍不显示编辑光标。拖选经过链接时不触发 Safari 打开。

WebKit 验证覆盖深 / 浅两种外观、跨正文与代码块的选择、原生复制后选区保持及 Markdown 不被修改。

| --- | --- | --- |
| 专注计时 | 专注中每秒一次；停止或会话析构时失效 | 必要；目前没有周期性 Safari 自动化轮询 |
| 环形菜单鼠标跟踪 | 菜单打开时约 90 Hz；关闭时停止 | 频率偏高但仅交互期间，未发现关闭后持续运行 |

| 笔记 / 日记页面 | 两页长期保留以保存草稿和滚动位置；隐藏页仍会接收数据更新 | 有意保留；大历史下有进一步缩小更新范围的空间 |

## 仍需留意的性能风险

1. **同步持久化仍在主线程。** 创建、完成 / 删除任务、标签重命名 / 合并、日志发送等最终编码并原子写入整个 journal；草稿虽 debounce，落盘仍在主线程。当前数据约 5 ms，但 10,000 日志已到约 141 ms。下一步宜引入有序后台保存队列、版本确认、退出时等待与失败重试，避免简单异步写造成旧快照覆盖新内容。本轮保留现有保存和错误处理语义。
2. **图片粘贴、导入、大图打开及首次缩略图解码仍有同步工作。** 多张大图或慢盘可能阻塞；缓存预算只控制保留成本，不能消除首次解码延迟。宜将读取与编码搬到后台，并给批量导入进度反馈。
3. **导出、备份恢复和部分历史查询仍是同步批处理。** 量大时可能短暂停顿；全文搜索、标签聚合与原生 Markdown 排版在超大历史 / 超长文档下仍需单独压测。已消除标签章节重复扫描，但未重写整个查询层。
4. **OCR 大积压缺少暂停 / 队列进度与细粒度取消。** 当前只有一个识别任务，避免并发爆发；仍可能在大量导入后持续占用 CPU。可按批次合并主线程结果写入，并提供暂停入口。
5. **撤销与缓存不是零成本。** UndoManager 已有 100 步上限，但每步的值类型快照仍可能保留历史数组；看板缓存上限为 6 个，NSCache 成本限制是软预算。不能把短期高占用直接判断为泄漏。

上述对象释放测试和空闲采样只能验证指定路径；不能据此证明整个应用在任意长时间使用、所有 WebKit 子进程及第三方库中都不存在内存泄漏。
