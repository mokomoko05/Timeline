## 实现记录

- 1：最近删除与历史迁入 SQLite recovery 表，与正文删除/覆盖同一事务；兼容旧 Trash.json 与 BoardHistory，旧文件损坏时停止写入并提示。保存失败保持内存修改并自动重试。
- 2：正文先发布；原图、保护清单单独报告失败，原图待发集合持久化并可重启续传。原图不压缩。
- 3：按设备流/回执/旧快照隔离错误，坏批次不推进接收序号，健康设备及本机继续交换。保留具体文件名，修复文件后自动重试。
- 4：通知变化检测包含活动任务集合，修复原提醒过期后完成任务仍残留推迟通知。双端提示调度错误；iOS 说明后台刷新受系统调度。
- 5：搜索匹配及拼音在后台 actor 执行；索引复用未变日志/工作板，内容变动重新搜索，取消旧请求。保持当前任务标签继承规则。
- 6：工作板自动保存不阻塞前台；显式提交等快照与写队列完成。后台生命周期增加系统时间保护。消除提交时重复的强制保存和额外主线程跳转。
- 7：双端显示设备及接收确认、显式停用。先持久化完整检查点，保留历史流与墓碑，重新上线使用新身份。旧版设备不支持停用，不开放按钮也不允许 API 绕过。
- 8：iOS 设置提供完整备份导出、预览、SHA-256 校验、恢复前本机快照及损坏库留档。备份含草稿、恢复记录、原图；拒绝缺图、逃逸链接、非法路径和重复实体。后台准备期间有新修改则取消覆盖。
- 9：双端设置区分本机保存、共享目录发布、iCloud 确认、对方合并回执；显示阶段耗时、积压字节、具体错误/等待文件。顶栏完成文字改为「本机同步完成」。
- 10：保存携带变更日期；SQLite 按实体比较/写入，outbox 独立行且与基线原子提交；增加日期索引与后台区间读取，iOS 日记只准备当前及相邻日正文；恢复快照在前台只复制值引用。

后续调整：第 10 项的日期索引和 `loadDays` 没有实际调用方（内容启动时都在内存里），索引还增加每次写入的成本，已于 2026-10-30 审计后移除；以后做数据库分页时再加回来。

## 验证与兼容性

- 全量隐藏测试：842 项，22 项按原有环境条件跳过，0 失败；ZZNoVisibleWindowsTests 通过，窗口服务器监测无可见测试窗口。后续新增/修改另跑相关测试，见验证记录。
- 真实旧代码混用（临时数据目录、独立 Swift 可执行程序）：7614602 以及 SQLite 改造前 34626f9 均通过新 Mac → 旧手机 → 新 Mac → 旧手机的双向编辑、完成、删除及原图字节验证；拒绝停用旧版设备。
- 手机目前无法升级；本轮不安装、不迁移手机数据。仅模拟器测量与编译验证，不能据此声称实际 iCloud 延迟或特定手机安装版本已经验证。
- iCloud Drive 仍使用 format 2 不可变增量 JSON，兼容现有增量版本。SQLite/outbox/recovery 仅在本机，不上传数据库文件。
- 首次启动仍将当前文档载入内存；本轮实现日期范围查询和页面按日准备，没有将全部界面改成数据库分页。不得宣称已实现全应用懒加载或消除 iCloud 系统调度延迟。

Mac 已通过 bash scripts/install.sh 保留数据安装并打开，安装前已生成迁移备份。iOS Release 模拟器最终构建通过；未安装到手机。提交与推送记录见本次 Git 提交。
