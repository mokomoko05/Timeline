# 增量持久化与 iOS 输入延迟实施记录

## 已实施的存储边界

双端共用 TimelineCore 的本机 `journal.sqlite`，通过系统 sqlite3 访问，不新增第三方数据库依赖。开启 WAL、`synchronous=FULL`，所有写入经过同一后台串行队列。数据库及 WAL/SHM 留在本地应用数据目录，云端继续使用 format 2 不可变 JSON 增量、检查点和回执。原图仍是独立文件，保持原始字节。

当前 schema 采用实体 payload，尚未拆成完整关系模型：

| 表 | 粒度 |
| --- | --- |
| entities | 每个 day 元信息、todo、log、board 一行；记录携带日期及排序位置 |
| sync_records | 每条同步记录一行，保留字段时间戳与删除标记 |
| metadata | journal 头、同步上下文、transport ledger（包括接收位置和待发送批次） |

修改正文时只编码并写入变化实体；日元信息没变时 SQL 不产生更新。同步正文、字段基线、游标和 outbox 在同一事务中提交，成功后才发布云端批次和回执。传输结果只更新 ledger。事务失败时全部回滚，缓存只在 COMMIT 后推进。

本机同步使用模型差异生成限定范围的记录更新，避免改单条日志还编码整个 `SyncContent.records()`；显式删除范围防止把未编码的记录误判为删除。本机归一化直接处理 Board 别名及任务编号；收到远端变化时仍会应用完整记录投影。

启动只解码一次同步基线，通过锁保护的已提交快照交给同步器，避免同步器再次排队等待启动备份并重复读库。

## 迁移、备份及恢复

1. 原始 journal、state、previous state、transport 先留存至 `Backups/before-sqlite-*`；保留与正文 commit ID 匹配的基线及通过设备/目录/commit 绑定校验的 ledger。
2. 临时数据库事务导入，重建模型及同步状态逐值校验，执行 `integrity_check`，checkpoint 后关闭，再切换文件入口。
3. SQLite 成为唯一权威数据。原 `journal.json` 是冻结的迁移源；导出功能从当前数据库投影生成最新 JSON。不能直接拿旧 journal 文件代表当前内容。
4. 启动备份在写队列生成；每日 JSON 快照最多一次，保留最近 30 天。迁移源及显式恢复前备份另行保留。运行中的数据库复制使用 SQLite backup API，包含已提交 WAL 内容。
5. 新库损坏时停止写入并进入只读，禁止默默回退到过时 JSON。显式恢复才留档原 DB/WAL/SHM 并重建数据库。需要回退旧版应用时，先从新版导出最新 JSON。

元数据丢失后重建基线会清理遗留同步记录，避免墓碑或旧内容混入新设备身份。迁移也覆盖空 Board 数组、跨日期移动、旧 Dayleaf 数据目录与不含 journal 头的异常数据库。

## iOS 交互调整

- 记一笔的呈现状态由 overlay 独立观察，开关卡片不触发整页日记重算。
- 每字变化只由输入桥接视图订阅；标题、附件选择器和工具按钮仅在是否有内容等状态切换时刷新。相机可用性缓存。
- 预热未挂载的 UITextView 并回收输入框，不抢焦点。首次呈现先经过两个显示帧再激活系统键盘；后续挂载立即获取焦点。系统首次键盘初始化仍会占用主线程。
- 保存异步等待后台持久化确认；期间禁止重复提交，成功后才清理草稿。失败保留草稿和待确认记录 ID，重试不重复新增日志。
- PerfProbe 直接向第一响应者输入，核对实际投递字符数；按上一个字符完成时间安排下一字，避免远期定时任务被系统批量合并。增加“保存记一笔”步骤，并记录持久化确认完成。

## 验证边界及后续方向

数据库事务回滚、损坏库保护、迁移失败不发布、旧数据留档、写队列顺序、同步失败恢复、跨日期移动、限定范围删除和附件生命周期均有针对性回归。故障验证使用 SQLite 事务中止注入，不等同于真机断电测试。

本轮先消除整库编码和写盘；内存中的 days 投影、撤销快照、实体相等比较和部分索引仍会随数据量增长。首次同步、远端合并、启动解码和周期备份仍有全量成本，transport ledger 也尚未拆成逐批次行。下一阶段应引入 dirty entity ID、按日期分页、索引局部更新，再细分 outbox 和 image_refs；不能声称所有操作已经达到与数据量无关的固定开销。

模拟器结果仅用于同环境对比；连接中的 iPhone 14 Pro Max 显示 unavailable，本轮没有完成真机延迟验证。

## 本轮验证与测量

375 项相关 XCTest，1 项按环境变量显式启用的本地副本基准跳过，0 失败。覆盖 TimelineCore、专注草稿、Board 编辑/切换/收藏拖动、快速记录关联、图片工具、笔记导航及可见窗口守门测试；窗口服务器监控 0 条可见测试窗口。iOS Release 双模拟器架构构建通过。

10,000 条日志的 macOS Debug 合成测试：

| 操作 | 结果 |
| --- | --- |
| 单条正文修改，强制同步保存 | 1 行实际更新，payload 146 B，物理 WAL 增长 4,152 B |
| 后台保存模式修改后同步 | 主线程修改 17.5 ms，同步 89.0 ms；同步提交 payload 3,378 B，WAL 增长 41,232 B，云端 493 B |

同步保存测试仍为 64.7 ms，包含主线程模型/撤销工作与等待写队列，不代表实际后台模式的逐字耗时。上一轮审计的 journal 约 3.38 MB、state 约 5.46 MB 整份写入已被替代；两轮合成文本不同，不能把旧同步 797 ms 与本次 89 ms 当作严格速度比。

iPhone 17 Pro / iOS 26.5 模拟器，Release、demoData、空记一笔草稿，基线为 34626f9。两端使用相同动作及修正后的输入驱动，动作 4 轮，输入 61 个字符全部投递并各采到 61 帧。未同时运行编译和测试。

| 指标 | 修改前 | 修改后 |
| --- | --- | --- |
| 首次打开记一笔到下一帧 | 76 ms | 48 ms |
| 后续 3 次打开 | 40 / 28 / 28 ms | 29 / 21 / 21 ms |
| 4 次关闭 | 51 / 35 / 36 / 36 ms | 41 / 28 / 28 / 28 ms |
| 首次打开后的最慢帧间隔 | 209 ms | 164 ms |
| 每字下一帧平均 / 中位 | 11.9 / 12.8 ms | 11.2 / 10.4 ms |
| 每字最慢 | 16.7 ms | 21.7 ms |

这组小样本支持卡片开关响应改善，不能声称逐字延迟有显著降低；最慢输入采样有波动。首次系统键盘初始化仍约 100 ms，整段仍会出现约 164 ms 停顿，未完全消除。

原图竞态步骤使用 4000×3000、1,552,696 B 的真实 PNG，在原图导入前额外延迟 2 秒以跨过关闭时刻。`blockedEarlySave=true`、`lateResultPersisted=true`；重新打开后异步保存确认 `completed=true`、`pending=false`。终止应用后直接以只读 SQLite 验证仅一条目标日志、原图存在且 `integrity_check=ok`。

这次含原图的保存动作到下一帧 119 ms、持久化确认总计 147.7 ms，页面刷新/关闭仍有峰值；后台写盘并不意味着界面刷新已无卡顿。该竞态步骤没有对应的旧版保存测量，不用它宣称保存速度提升。下一步应在真机分析保存后的日记布局与派生索引刷新，并以同数据集增加重复采样。
